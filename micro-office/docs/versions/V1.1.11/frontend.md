# V1.1.11 前端拆解

## 1. 线程目标

- 在 Micro Office 后台新增“日常条目管理”页面。
- 保持门户模板与 block 设计模型不变。
- 让条目管理和 block/template 管理入口清晰分离。

## 2. 必做项

### 2.1 新增“日常条目管理”入口

建议新增后台菜单或页面入口：

- `日常条目管理`

该入口不放在：

- 门户模板设计页内部
- 卡片块定义页内部

### 2.2 列表页

列表至少展示：

- 条目名称
- 条目编码
- 状态
- 排序
- 适用范围摘要
- 会话策略摘要
- 最近更新时间

### 2.3 新建 / 编辑页

表单至少分成三个区域：

1. 条目基础信息
   - name
   - code
   - sortOrder
   - status
   - meta（如图标、备注）

2. 适用范围
   - 全局可见 / 指定组织 / 指定用户

3. 聊天配置
   - 会话解析策略
   - 共享群 / 个人群
   - 绑定摘要

### 2.4 与 block 的边界提示

在产品交互上要明确：

- block 不逐条管理“请假 / 报销 / 会议”
- 条目页负责业务条目
- block 页负责 `daily_list` 这类容器资产

### 2.5 不污染模板页

- 模板页不新增条目级 schema
- 模板继续只引用 `daily_list`
- 不在模板页里内嵌条目编辑器

## 3. 前端验收标准

- 后台存在独立“日常条目管理”页面
- 用户能完成条目增删改查与状态切换
- 页面能表达适用范围与聊天策略
- block/template 页面职责不被混淆

## 4. 重点改动文件

可能涉及：

- `frontend/src/pages/admin/*`
- `frontend/src/components/admin/*`
- `frontend/src/api/index.ts`
- 后台菜单或路由配置文件

## 5. 非目标

- 不改门户运行时卡片渲染协议
- 不在前端做 DAILY_ENTRY 特殊分流
- 不让 block 页面承担条目管理职责
