# V1.1.8 概览（门户卡片管理列表信息语义纠偏）

## 1. 版本目标

- 将“门户卡片管理”页面改成真正的**卡片资产列表**，不再展示门户模板来源、legacy 技术编码、UUID 尾巴等内部实现信息。
- 让列表中的“卡片块”列只表达**卡片块本身**，不再表达“它从哪个门户模板拆出来”。
- 删除“更新时间”列，保留对用户真正有意义的卡片资产信息。

## 2. 当前问题

当前 [门户卡片管理] 页面存在以下问题：

1. `卡片块`列语义错误
   - 现在显示的是 legacy code、门户模板衍生编码、拼接型技术名。
   - 例如：
     - `LEGACY_PERSON_POSITION_SALES_MANAGER_MESSAGE_...`
     - `CEO岗位驾驶舱模板V1 / 协作工作通知`
   - 这些不是“卡片块名称”，而是历史实现痕迹。

2. 卡片和门户模板没有真正分开
   - 页面明明是“卡片管理”，却仍然在主信息中暴露模板来源。

3. 内部技术信息直接暴露给用户
   - UUID 尾巴、legacy 前缀、portal item 派生编码不应出现在管理列表主视图。

4. `更新时间`列噪音大于价值
   - 本页面的主要任务是识别、管理和复用卡片资产，不需要更新时间参与决策。

## 3. 本版产品结论

### 3.1 卡片块名称只显示资产名称

- `卡片块`列只显示独立卡片块名称。
- 不显示：
  - 门户模板名称
  - legacy 编码
  - UUID
  - 派生 code

示例：

- 现在：`CEO岗位驾驶舱模板V1 / 协作工作通知`
- 改后：`协作工作通知`

- 现在：`LEGACY_PERSON_POSITION_SALES_MANAGER_MESSAGE_9BA851E6_...`
- 改后：应显示修正后的卡片资产名称，而不是这串技术编码。

### 3.2 页面不表达模板来源

- 模板来源不属于卡片资产主列表信息。
- 本页面不再承载“它原来属于哪个门户模板”的展示责任。

### 3.3 数据修复走数据库，不做前端兜底

- 不是前端简单截断字符串。
- 需要数据库线程把卡片块资产数据修正到最新语义：
  - name 是真正的卡片资产名
  - 不是 legacy 派生名
- 前后端直接按最新数据工作，不做旧版展示兼容。

## 4. In / Out

### In Scope

- 门户卡片管理列表页字段调整
- 卡片块名称口径修正
- legacy/UUID/模板来源显示移除
- 更新时间列移除
- 数据库回填卡片块名称

### Out of Scope

- 不改门户卡片编辑页整体表单结构
- 不改正式业务门户展示页
- 不补“模板来源”替代显示字段
- 不做旧版命名兼容展示

## 5. 实现口径

### 5.1 前端

- 调整 [AdminPortalBlockTemplatePage.tsx] 的列表列：
  - `卡片块`只显示卡片资产名称
  - 不再显示 `code`
  - 删除 `更新时间`

### 5.2 后端

- 卡片块列表接口返回的 `name` 必须是用户可读、与模板解耦的卡片资产名称。
- 不再把模板来源、legacy 迁移信息拼进列表主显示字段。

### 5.3 数据库

- 修正历史回填生成的 block template 名称。
- 清理由 `V44__converge_portal_templates_to_block_refs.sql` 产生的 legacy 命名结果。
- 以卡片自身语义重新命名，不保留模板耦合信息。

## 6. 关键风险

1. **只改前端不改数据**
   - 会变成前端遮羞，后端和数据库仍然是脏语义。

2. **名称清洗规则不明确**
   - 如果数据库回填没有明确规则，可能出现大量“基础信息1/通知2”之类无意义名称。

3. **把模板来源误当作资产名**
   - 会继续破坏“卡片和门户模板彻底分开”的目标。

## 7. 验收口径

- 卡片管理列表不再显示 `LEGACY_*` 文本。
- 卡片管理列表不再显示门户模板名拼接信息。
- 卡片管理列表不再显示 `更新时间` 列。
- `卡片块`列只显示用户可理解的独立卡片名。
- 前后端不依赖旧版展示兼容，数据通过数据库修正到最新口径。
