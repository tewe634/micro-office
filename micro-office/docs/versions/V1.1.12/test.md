# V1.1.12 测试拆解

## 1. 测试目标

- 验证“工作汇报会议”点击后先弹窗输入会议名。
- 验证输入后能成功创建新群并跳转。
- 验证其他日常条目行为不受影响。

## 2. 核心用例

### 2.1 弹窗出现

- 点击“工作汇报会议”后出现输入弹窗
- 不再直接跳群

### 2.2 输入校验

- 空名称不能创建
- 超长名称提示清晰

### 2.3 创建成功

- 输入合法会议名后创建成功
- 群标题等于输入名称
- 自动跳转到新群

### 2.4 群内后续行为

- 新群内仍可继续创建工作流

### 2.5 回归

- 请假 / 报销等其他日常条目维持原逻辑
- 普通打开群能力不受影响

## 3. 验收标准

- “工作汇报会议”链路符合“先输入、后创建、再跳转”
- 标题命名正确
- 其他条目无误伤

## 4. 残余风险关注

- 前端仅做条目名硬编码识别的扩展性风险
- 后端新创建链路与旧打开链路的边界是否清楚
