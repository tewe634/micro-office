# V1.1.12 前端拆解

## 1. 线程目标

- 为“工作汇报会议”条目新增点击前弹窗。
- 支持输入会议名后调用创建接口，并在成功后进入新群。
- 不影响 `daily_list` 其他条目现有行为。

## 2. 必做项

### 2.1 条目点击识别

- 在日常条目点击链路中识别“工作汇报会议”这一条目。
- 对该条目不再直接执行原来的打开/创建跳转。

### 2.2 弹窗交互

新增弹窗：

- 标题：创建工作汇报会议
- 输入项：会议名称
- 操作：取消 / 创建并进入

### 2.3 表单校验

至少要求：

- 名称必填
- 去除纯空格输入
- 错误提示可见

### 2.4 创建并跳转

- 前端调用后端创建接口
- 成功后使用返回的 `sessionId` 进入会话
- 失败时保留弹窗并提示错误

### 2.5 不污染其他条目

- 请假 / 报销 / 其他条目继续走原有链路
- 不把“先弹窗”变成 `daily_list` 全局默认行为

## 3. 前端验收标准

- 点击“工作汇报会议”必定先弹窗
- 不输入名称无法创建
- 输入有效名称后成功进入新群
- 其他日常条目行为不回归

## 4. 重点改动文件

可能涉及：

- `frontend/src/pages/portal/*`
- `frontend/src/components/*`
- `frontend/src/api/index.ts`

## 5. 非目标

- 不改 block/template 模型
- 不新增整个日常条目动作设计器
- 不重构所有日常条目动作分发
