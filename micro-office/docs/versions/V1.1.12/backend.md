# V1.1.12 后端拆解

## 1. 线程目标

- 为“工作汇报会议”提供“先输入名称，再创建并打开群”的后端能力。
- 明确区分“打开已有/已解析会话”和“创建新会话后打开”两类能力。

## 2. 必做项

### 2.1 新增创建接口

提供一个后端接口，用于：

- 接收会议名称
- 创建会议群
- 返回新会话信息

请求至少包含：

- 条目标识
- `meeting_name`
- 当前用户上下文

### 2.2 创建规则

后端负责：

- 校验会议名称
- 创建新群/会话
- 以会议名称作为群标题
- 记录该群来源于“工作汇报会议”条目

### 2.3 返回统一结果

返回至少包含：

- `sessionId`
- `sessionTitle`
- `sessionType`

### 2.4 与原 DAILY_ENTRY 打开链路的边界

本版需要明确：

- “工作汇报会议”不再走原先的“直接打开/直接解析”主路径
- 它属于“创建后打开”链路
- 不影响其他 DAILY_ENTRY 条目继续按现有策略打开

### 2.5 文档更新

同步更新：

- `api-design.md`

说明：

- 哪个接口负责创建会议群
- 与 `open-workbench-session` 的区别

## 3. 后端验收标准

- 后端可按会议名称成功创建新群
- 返回结果可供前端直接跳转
- 非会议条目不被误切到新链路

## 4. 重点改动文件

可能涉及：

- `PortalRuntimeController.java`
- `PortalRuntimeSessionService.java`
- 相关 service / repository
- `api-design.md`

## 5. 非目标

- 不改群内工作流能力
- 不把所有 DAILY_ENTRY 都改成创建型动作
- 不在模板 schema 增加复杂前置表单配置
