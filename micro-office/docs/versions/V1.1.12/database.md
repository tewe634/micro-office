# V1.1.12 数据库拆解

## 1. 线程目标

- 评估“工作汇报会议按名称创建新群”是否需要新增字段、关系或映射。
- 给出最小数据库改造方案。

## 2. 必做项

### 2.1 现状评估

数据库线程先确认当前会话表/关系表是否已经足够承载：

- 群标题 = 本次会议名称
- 会话来源 = 工作汇报会议条目

### 2.2 最小改造原则

优先级：

1. 若现有会话表已有标题与元数据字段可承载，则不新增表
2. 若缺少“来源条目”识别能力，再补最小字段或关系
3. 不为单一需求引入过重的新表设计

### 2.3 若需改造，建议方向

可能涉及：

- 会话表元数据补充来源标记
- 会话与条目标识的关系字段
- 创建链路所需索引

### 2.4 校验 SQL

输出校验 SQL，验证：

- 新建会议群是否带正确标题
- 是否可识别来源条目
- 是否未破坏现有会话数据

## 3. 数据库验收标准

- 数据层可支撑会议名创建新群
- 不引入与条目管理无关的复杂新结构
- 不影响现有普通会话链路

## 4. 非目标

- 不重做整个日常条目表结构
- 不为本版扩展通用表单引擎
