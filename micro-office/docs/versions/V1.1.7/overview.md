# V1.1.7 概览（门户模板入口重构与两层模型收敛）

## 1. 版本目标

- 把当前“门户模板”产品重构成两个明确模块：
  1. **卡片块定义模块**
  2. **岗位/对象模板设计模块**
- 让用户一眼看懂：
  - 什么地方定义单个卡片块
  - 什么地方给岗位或对象模板引用这些卡片块
- 删除当前不符合新模型的旧入口、旧编辑心智、旧兼容逻辑，不保留“双轨制”产品形态。

## 2. 当前产品问题

基于当前代码与页面现状，存在以下偏差：

1. **卡片块定义模块没有可见入口**
   - 虽然已有 `/admin/portal-block-templates` 路由与页面代码，但菜单、标题、选中态、权限链路未完整接入。
   - 对用户而言等于“没有这个模块”。

2. **门户模板首页信息架构错误**
   - 当前首页只有：
     - `按岗位生成模板`
     - `模板列表`
   - 缺少：
     - `卡片块定义` 的可见入口
     - `对象模板新建` 的业务化入口

3. **岗位模板编辑页职责不对**
   - 当前模板编辑页仍以 `section/items/actions` 为主心智。
   - 这会让“岗位模板设计页”继续承担“重新定义卡片块”的职责，而不是“引用已有卡片块做装配”。

4. **对象模板创建入口不符合业务语义**
   - 现在只有一个泛化的“新建空模板”按钮。
   - 缺少显式对象入口：
     - 客户模板
     - 供应商模板
     - 承运商模板
     - 银行模板
     - 产品模板
     - 组织模板

## 3. 本版产品结论

### 3.1 产品层明确拆成两个模块

#### 模块 A：卡片块定义

职责：

- 定义单个卡片块资产
- 管理块的：
  - 名称
  - 编码
  - 展示类型
  - 数据键
  - 标题
  - 动作
  - meta

典型块：

- 消息中心
- 待办列表
- 销售简报
- 客户提醒

#### 模块 B：模板设计

职责：

- 给岗位模板或对象模板**引用**卡片块
- 管理：
  - 引用了哪些卡片块
  - 顺序怎么排
  - 放在哪个分区
  - 是否启用

本模块**不负责重新定义块内部字段**。

### 3.2 首页信息架构重做

门户模板首页重构成以下三块：

1. `按岗位生成模板`
2. `对象模板新建`
3. `模板列表`

同时新增全局可见入口：

4. `卡片块定义`

### 3.3 最新版单路径原则

本版明确执行以下规则：

- 不保留旧产品心智并行存在
- 不做旧版兼容兜底
- 不在前端保留“内嵌 item/action 编辑”作为默认主路径
- 不通过后端 fallback 同时兼容旧结构与新结构作为长期方案
- 数据结构变化由数据库线程负责 migration / backfill
- 旧代码、旧入口、旧编辑逻辑该删就删

## 4. In / Out

### In Scope

- 门户模板首页重构
- 系统管理菜单接入“卡片块定义”
- 卡片块定义模块正式可见、可访问、可管理
- 模板设计页改成“引用卡片块装配模板”
- 新增对象模板业务化新建入口
- 数据模型按最新结构收敛，不保留旧版主路径

### Out of Scope

- 不做正式业务门户展示页视觉重构
- 不引入无限制低代码平台
- 不做块级复杂脚本/表达式引擎
- 不保留历史模板数据的自动兼容渲染策略

## 5. 页面与交互口径

### 5.1 首页

首页应至少有以下可见区域：

1. `按岗位生成模板`
   - 继续保留

2. `对象模板新建`
   - 至少提供按钮：
     - 新建客户模板
     - 新建供应商模板
     - 新建承运商模板
     - 新建银行模板
     - 新建产品模板
     - 新建组织模板

3. `模板列表`
   - 查看已有模板并进入编辑

4. `卡片块定义`
   - 入口可在首页卡片、顶部按钮或系统管理菜单中体现
   - 但必须是用户可发现的正式入口

### 5.2 模板设计页

改造目标：

- 模板设计页的主操作从“编辑 section/items/actions”
- 改为“为模板引用卡片块”

允许操作：

- 新增分区
- 选择卡片块
- 调整顺序
- 启停引用

不允许作为主路径继续做：

- 在模板页里手改 `dataKey`
- 在模板页里手改 `displayType`
- 在模板页里手改 `actions`

这些属于“卡片块定义模块”。

## 6. 数据与实现原则

1. 数据库线程负责：
   - 新结构 migration
   - 旧结构清理
   - 数据 backfill

2. 后端线程负责：
   - 删除旧 fallback
   - 删除旧兼容解析
   - 让 API 只对最新结构负责

3. 前端线程负责：
   - 删除旧入口和旧主交互
   - 不再保留旧编辑模式作为默认路径

## 7. 关键风险

1. **删旧代码不彻底**
   - 若仍保留旧 items/actions 编辑主路径，产品心智会继续混乱。

2. **只改页面，不改数据**
   - 若新 UI 只是包了一层壳，但底层还走旧结构，最终会再次回到“双轨制”。

3. **入口补了，但权限/菜单没补齐**
   - 会再次出现“页面存在但用户看不到”的问题。

4. **对象模板入口仍做成泛化弹窗**
   - 会继续偏离业务语义。

## 8. 验收口径

- 用户能明确看到“卡片块定义”入口。
- 首页能明确看到对象模板新建入口，而不是只剩“新建空模板”。
- 模板设计页默认走“引用卡片块”主路径。
- 旧 `section/items/actions` 设计主路径被移除，不再作为默认模式存在。
- 旧数据通过数据库迁移整理到最新结构，不要求前后端做旧版兜底兼容。
