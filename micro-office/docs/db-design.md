# micro-office 数据库设计文档

## 1. 文档目标

为数据库线程提供结构化边界：哪些表是当前系统事实源，迁移如何演进，哪些约束必须保证。

## 2. 数据库栈

- PostgreSQL
- Flyway 版本迁移
- 迁移路径：`backend/src/main/resources/db/migration`

## 3. 设计原则

- 不修改历史迁移，新增版本迁移
- 核心事实优先结构化字段，不把主事实塞进 JSON
- 约束与索引必须有查询路径依据
- 与 API 合同一致，避免“库层语义与接口语义分裂”

## 4. 当前数据域

- 主数据域：organization、position、sys_user、external_object、product 及权限相关表
- 门户模板域：模板、区块、条目、动作等配置表
- 会话与认证域：auth_session 等

## 5. 迁移策略

- 所有变更通过新 migration 文件交付
- 数据修复脚本要可审计
- 对大表或高频查询变更应附带索引评估

## 6. 重点风险

- 权限相关表与业务规则耦合高，改动需先做影响评估
- 门户模板运行时相关字段变更需同步后端装配逻辑
- 历史字段兼容期内不能直接硬删除

## 7. 验证要求

- migration 可在全新库顺序执行
- migration 可在已有环境增量执行
- 对关键查询路径有基本性能验证
