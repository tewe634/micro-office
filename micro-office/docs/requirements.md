# micro-office 需求文档

## 1. 文档信息

- 产品名称：micro-office
- 文档版本：v1.0
- 文档状态：当前基线
- 文档目标：固化“当前系统边界 + 下一阶段演进方向”，支持多线程并行开发。

## 2. 产品定位

micro-office 当前定位为企业内“主数据 + 权限 + 门户聚合”系统，核心覆盖：

- 组织、岗位、人员主数据管理
- 外部对象（客户/供应商/银行等）主数据管理
- 产品主数据管理
- 菜单与对象类型权限管理
- 人员/对象/产品门户聚合展示
- 销售协同模板与组织绑定配置

## 3. 当前范围（In Scope）

- 认证与会话管理
- 组织管理 `/api/orgs`
- 岗位管理 `/api/positions`
- 人员管理 `/api/users`
- 外部对象管理 `/api/objects`
- 产品管理 `/api/products`
- 门户聚合 `/api/portal/*`
- 门户模板管理 `/api/admin/portal-templates/*`
- 门户运行时 `/api/portal-runtime/*`
- 权限配置 `/api/admin/permissions*`
- 销售协同配置 `/api/admin/sales-collab/*`

## 4. 不在当前范围（Out of Scope）

- 旧版工作流 runtime（threads/nodes/comments/workbench/clock）
- 任务池、打卡等已下线模块
- 独立流程引擎设计器

## 5. 当前关键业务规则

- 菜单权限：角色权限 + 用户级覆盖
- 对象类型权限：岗位并集 + 用户级覆盖
- 数据范围：优先按组织范围和角色能力收敛
- 门户聚合：支持岗位上下文与 scope 概念，但当前能力存在版本差异

## 6. 下一阶段需求主线

- 主线 A：门户链路一致性修复（前端路由/API 与后端实际能力对齐）
- 主线 B：门户模板运行时能力增强（模板、契约、数据集装配）
- 主线 C：权限与范围规则可测化（最小回归闭环）
- 主线 D：测试基线建设（API smoke + 多岗位/scope 回归）

## 7. 验收基线

- 主要业务接口可通过 smoke 用例
- 门户入口可稳定打开并可切换上下文（在当前版本能力范围内）
- 权限场景（菜单、对象类型、组织范围）可复现、可验证
- 文档与代码保持同步，不允许“代码已变、文档失真”
