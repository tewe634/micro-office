# micro-office 权限矩阵文档

## 1. 文档目标

统一角色、资源、动作边界，避免“前端可见、后端拒绝”或“前端隐藏、后端可写”的不一致。

## 2. 角色分层

- 管理角色：`ADMIN`
- 业务角色：`HR`、`SALES`、`FINANCE`、`PURCHASE`、`TECH`、`STAFF` 等

## 3. 权限判定原则

- 后端是最终判定者，前端只做展示控制
- 用户多角色场景按并集处理
- 用户级覆盖优先级高于角色默认

## 4. 资源与动作

主要资源：

- 组织、岗位、人员、对象、产品
- 门户页面
- 权限配置
- 销售协同配置
- 门户模板配置

主要动作：

- 查询、创建、编辑、删除
- 配置保存
- 门户访问

## 5. 高级规则

- 菜单权限：`role_menu_permission` + `user_menu_permission`
- 对象类型权限：`position_object_type` + `user_object_type`
- 数据范围：由组织范围与角色能力共同决定
- 组织范围命中规则：目标对象组织必须是“可见组织节点本身或其下级节点”，不允许子组织范围反向访问父组织数据
- 对象类型空集策略：对非全局管理员，若未命中任何对象类型权限，则视为无对象访问权限（不再按“空=全部”放行）
- 产品写权限：除菜单权限外，`STAFF` 不允许新增/修改/删除产品

## 6. 最小矩阵（建议）

| 动作 | ADMIN | HR | SALES/其他业务角色 | STAFF |
|---|---|---|---|---|
| 查看主数据页面 | Y | Y | C | C |
| 编辑组织/岗位/人员 | Y | Y | N | N |
| 编辑对象/产品 | Y | C | C | N |
| 访问对象/产品门户 | Y | C | C | C |
| 配置权限 | Y | N | N | N |
| 配置销售协同 | Y | N | N | N |
| 配置门户模板 | Y | N | N | N |

说明：`C` 表示受组织范围、对象类型权限、菜单权限等条件约束。

## 7. 落地要求

- 前端按钮展示应依赖能力或菜单返回
- 后端写接口必须二次鉴权
- 权限变更应纳入回归测试
