# V1.1.13 数据库拆解

## 1. 线程目标

- 给“日常条目行为配置”提供明确数据库口径。
- 让行为配置绑定在日常条目上，而不是 block 动作上。
- 为首个“输入群聊主题创建群聊”场景提供最小结构支持。

## 2. 必做项

### 2.1 行为配置落位

数据库线程需要明确：

- 行为配置是否落在日常条目主表扩展字段
- 还是新增“日常条目行为表 / 字段表”

要求：

- 结构化
- 可扩展
- 不做无边界 JSON 堆叠

本版落地选择：

- 新增“日常条目行为主表 + 行为字段子表”：
  - `mo_daily_entry_behaviors`
  - `mo_daily_entry_behavior_form_fields`
- 不再把条目行为配置继续挂在 `mo_portal_block_template_actions`。
- migration：
  - `backend/src/main/resources/db/migration/V51__daily_entry_behavior_config.sql`

### 2.2 字段配置落位

至少能表达：

- 前置弹窗开关
- 弹窗标题
- 确认按钮文案
- 字段定义
- 字段顺序

### 2.3 首个场景数据支持

确认首个场景需要的数据支持：

- `session_title` 输入字段配置
- 创建群聊的执行动作配置
- 如有必要，创建后来源标记

### 2.4 校验 SQL

输出校验 SQL，至少覆盖：

- 条目行为配置存在性
- 字段配置完整性
- 会议条目行为配置读取正确

校验脚本：

- `docs/versions/V1.1.13/database-sql.sql`

## 3. 数据库验收标准

- 日常条目行为配置有明确结构
- 不继续挂在 block 动作上
- 首个场景可被完整表达

## 4. 非目标

- 不重做整个日常条目主表体系
- 不扩展成完整低代码表单引擎数据库模型
