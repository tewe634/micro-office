# V1.1.13 后端拆解

## 1. 线程目标

- 为日常条目提供行为配置读取与执行能力。
- 让运行时根据“条目行为配置”执行动作，而不是根据 block 或条目名称硬编码。
- 跑通会议条目“输入群聊主题后创建群聊”的首个场景。

## 2. 必做项

### 2.1 条目行为配置接口

补齐日常条目管理接口，使其支持保存和读取：

- 动作类型
- 前置弹窗开关
- 弹窗标题
- 确认按钮文案
- 字段定义

### 2.2 运行时条目行为读取

`daily_list` 输出条目时，需要把行为配置带到运行时可消费结构中，或保证点击时可按条目 id 查询到行为配置。

### 2.3 动作执行能力

后端需要支持：

- 接收条目点击后的前置参数
- 校验参数
- 执行对应动作

首个场景：

- `session_title`
- 创建群聊
- 返回新会话

### 2.4 去除错误挂载点

本版后端口径要明确：

- 这不是 block 动作配置主路径
- 行为归属日常条目

### 2.5 文档更新

同步更新：

- `api-design.md`

明确：

- 日常条目管理接口新增哪些行为字段
- 运行时如何执行条目行为

## 3. 后端验收标准

- 条目行为配置可保存、可读取
- 运行时点击条目可按配置执行
- 会议条目首个场景跑通
- 不依赖“会议”名称硬编码

## 4. 重点改动文件

可能涉及：

- 日常条目 admin controller / service
- `PortalRuntimeController.java`
- `PortalRuntimeSessionService.java`
- `api-design.md`

## 5. 非目标

- 不继续扩展 block 页动作配置
- 不把条目行为做成只前端可见的假配置
- 不做所有动作类型的大而全改造
