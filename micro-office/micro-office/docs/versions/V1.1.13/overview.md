# V1.1.13 概览（日常条目行为支持前置弹窗）

## 1. 版本目标

- 在“日常条目管理”中新增条目行为配置能力。
- 支持日常条目点击后先弹窗收集参数，再执行后续动作。
- 明确前置弹窗行为只属于“日常条目”侧，不属于“门户卡片块”侧。
- 跑通首个场景：会议条目点击后先输入群聊主题，再创建群聊并跳转。

## 2. 基线理解

- `daily_list` 是门户里的集合型容器 block，负责展示日常条目集合。
- 门户卡片管理页负责卡片块资产定义，不应逐条维护“请假 / 报销 / 会议”的业务行为。
- 日常条目管理页负责业务条目本身，目前已有：
  - 名称
  - 编码
  - 排序
  - 状态
  - Meta
  - 适用范围
- 现在的问题是：会议等条目需要自己的点击行为配置，但条目页还没有这块能力。

## 3. 本版设计结论

### 3.1 行为配置挂在日常条目上

本版明确：

- 前置弹窗行为配置挂在“日常条目”
- 不挂在“门户卡片块”

也就是说：

- block 继续只负责 `daily_list` 容器定义
- 条目负责“点了以后做什么”

### 3.2 条目行为模型

日常条目至少要支持：

- 是否启用点击行为
- 动作类型
- 是否启用前置弹窗
- 弹窗标题
- 确认按钮文案
- 弹窗字段定义
- 后续执行动作配置

### 3.3 首个落地场景

首个使用场景是“会议”条目：

1. 用户点击“会议”
2. 弹出输入群聊主题弹窗
3. 用户输入主题
4. 后端按主题创建群聊
5. 前端进入新群

但能力本身属于“条目行为配置”，不是“会议专属硬编码逻辑”。

### 3.4 block 与条目的职责边界

#### block 侧

- 定义 `daily_list`
- 被模板引用
- 不负责配置具体条目行为

#### 条目侧

- 管理“会议 / 请假 / 报销”等业务条目
- 管理条目适用范围
- 管理条目点击后的行为

### 3.5 执行动作口径

条目行为最终仍需落到可执行动作，例如：

- 创建群聊并跳转
- 打开现有工作台会话
- 其他后续版本可能扩展的动作

本版首个必做动作是：

- 输入 `session_title` 后创建群聊并跳转

## 4. In / Out

### In Scope

- 日常条目页新增“行为配置”区块
- 支持前置弹窗配置
- 支持前置字段配置
- 支持首个“输入群聊主题创建群聊”场景

### Out of Scope

- 不把前置弹窗能力继续放到门户卡片管理页作为主目标
- 不重做 block/template 模型
- 不要求所有日常条目都必须配置弹窗
- 不做复杂多步表单引擎

## 5. 页面口径

### 5.1 日常条目编辑页新增区块

建议新增：

- `行为配置`

至少包含：

- 动作类型
- 启用前置弹窗
- 弹窗标题
- 确认按钮文案
- 字段列表

### 5.2 字段模型建议

首版至少支持：

- 文本输入字段

最小属性：

- `fieldKey`
- `label`
- `inputType`
- `required`
- `placeholder`
- `maxLength`
- `sortOrder`

## 6. 后端与数据口径

- 后端按日常条目行为配置决定点击后如何执行
- 不依赖条目名称硬编码
- 行为配置要有结构化存储口径
- 会议条目只是第一个使用者

## 7. 依赖顺序

1. 数据库先给出日常条目行为配置的存储口径。
2. 后端提供条目行为读取与执行能力。
3. 前端在日常条目编辑页增加行为配置区块，并在运行时执行。
4. 测试验证条目行为、弹窗、创建群聊和回归链路。

## 8. 关键风险

1. **继续把行为挂在 block 上**
   - 会再次把条目行为和容器资产混在一起。

2. **会议条目做成硬编码**
   - 会失去条目行为配置的意义。

3. **行为配置只有 UI，没有运行时接入**
   - 会出现条目页能配、点击时不生效的假能力。

## 9. 验收口径

- 日常条目编辑页存在“行为配置”区块。
- 会议条目可配置“前置弹窗 + 输入群聊主题 + 创建群聊并跳转”。
- `daily_list` block 无需新增行为配置即可消费条目。
- 门户卡片管理不是本版前置弹窗配置主入口。
