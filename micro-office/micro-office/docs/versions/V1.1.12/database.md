# V1.1.12 数据库拆解

## 1. 线程目标

- 评估并落地“前置弹窗参数动作”所需的最小数据库支持。
- 给出动作配置结构化存储的数据库口径。
- 跑通首个“群聊主题创建群聊”场景的最小数据结构。

## 2. 必做项

### 2.1 动作配置落位评估

数据库线程需要确认：

- 现有 `mo_portal_block_template_actions` 是否足以承载“前置弹窗字段配置”
- 若不足，应该新增哪些结构化字段或关系表

要求：

- 不把这类配置长期塞在无边界 JSON 里
- 不为单一场景写死“会议名”字段

### 2.2 配置模型建议

至少要能表达：

- 动作是否需要前置弹窗
- 弹窗字段定义
- 字段顺序
- 字段校验约束

数据库线程可在以下两路中选最合适的一路：

1. 给动作表补最小结构化字段
2. 新增动作前置字段子表

但需要显式比较，不要隐性假设。

本版落地选择：

- 采用“动作表补最小结构化字段 + 新增前置字段子表”方案。
- migration：
  - `backend/src/main/resources/db/migration/V50__pre_action_modal_form_config.sql`

### 2.3 首个场景数据承载

首个场景“群聊主题创建群聊”需要确认：

- 会话标题是否已有字段可直接存
- 是否需要补来源动作/来源条目标记
- 是否需要新增关系或元数据约束

### 2.4 校验 SQL

输出校验 SQL，至少覆盖：

- 动作配置是否完整
- 前置字段定义是否可正确读取
- 创建出的群标题是否落对

校验脚本：

- `docs/versions/V1.1.12/database-sql.sql`

## 3. 数据库验收标准

- 动作前置弹窗配置有明确存储口径
- 首个场景不依赖前端硬编码字段
- 不引入过重的新表设计

## 4. 非目标

- 不重做整个模板结构
- 不做完整表单引擎数据库模型
