# V1.1.12 后端拆解

## 1. 线程目标

- 为门户动作体系提供“带前置参数的动作执行”后端能力。
- 明确动作配置、参数校验、执行结果返回的统一口径。
- 跑通首个场景：“输入群聊主题后创建群聊并返回新会话”。

## 2. 必做项

### 2.1 动作配置承载

后端需要明确动作配置如何表达：

- 是否需要前置弹窗
- 需要哪些字段
- 字段如何映射到后端动作参数

要求：

- 配置结构化
- 不靠条目名称猜测

### 2.2 执行接口

提供统一后端接口或扩展现有动作执行接口，用于：

- 接收动作上下文
- 接收前置参数
- 执行真实业务动作

### 2.3 首个场景执行

首个场景至少支持：

- 参数：`session_title`
- 动作：创建新群聊 / 会话
- 返回：新 `sessionId`

### 2.4 统一返回结构

返回结果至少要能表达：

- 执行是否成功
- 是否产生新会话
- 新会话 id / 标题
- 前端后续如何处理

### 2.5 文档更新

同步更新：

- `api-design.md`

明确：

- 动作执行接口如何接收前置参数
- 首个创建群聊场景如何调用

## 3. 后端验收标准

- 后端支持按动作配置接收前置参数并执行
- 创建群聊场景可用
- 不依赖“工作汇报会议”名称硬编码
- 原有直接动作链路保持可用

## 4. 重点改动文件

可能涉及：

- `PortalRuntimeController.java`
- `PortalRuntimeSessionService.java`
- 动作解析 / 执行相关 service
- `api-design.md`

## 5. 非目标

- 不重做所有业务动作
- 不把动作系统扩展成完整编排引擎
- 不为单个条目保留硬编码专属分支
