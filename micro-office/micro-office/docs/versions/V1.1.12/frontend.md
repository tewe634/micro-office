# V1.1.12 前端拆解

## 1. 线程目标

- 为门户动作体系新增“前置弹窗参数收集”前端能力。
- 支持按动作配置动态弹窗，而不是按条目名称硬编码弹窗。
- 跑通首个场景：“输入群聊主题后创建群聊并跳转”。

## 2. 必做项

### 2.1 动作配置识别

- 前端动作分发层需要能识别：
  - 哪个动作需要前置弹窗
  - 弹窗需要哪些字段

### 2.2 通用弹窗组件

新增或抽象一个可复用弹窗组件，至少支持：

- 文本输入字段
- 必填校验
- 占位提示
- 取消 / 确认

### 2.3 动作提交流程

- 用户确认后，将表单参数与动作原始上下文一起提交后端
- 后端返回结果后：
  - 若是会话创建成功，则跳转进入
  - 若失败，则提示错误并保留当前上下文

### 2.4 首个场景接入

跑通“群聊主题输入后创建群聊”：

- 弹窗输入 `session_title`
- 成功后进入新群

### 2.5 保持旧动作不回归

- 未配置前置弹窗的动作继续按原逻辑执行
- 不把弹窗变成所有动作的默认流程

## 3. 前端验收标准

- 前端可按动作配置决定是否弹窗
- 通用弹窗字段可正确渲染和校验
- 首个创建群聊场景跑通
- 旧动作链路不受影响

## 4. 重点改动文件

可能涉及：

- `frontend/src/pages/portal/*`
- `frontend/src/components/*`
- `frontend/src/api/index.ts`
- 动作分发相关模块

## 5. 非目标

- 不改 block/template 主结构
- 不做完整低代码表单引擎
- 不把所有动作都重写一遍
